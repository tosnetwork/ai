token call records, confirmations, receipts and exports select explicit versions.

## Scope and review

The token wallet's pinned code transfers its principal without a transfer fee;
this does not claim support for arbitrary fee-charging wallet code. A real
independent-provider purchase and independent evidence verification remain the
network acceptance gate. Provider execution/delivery changes belong to their
own work item.

Upstream comparison: these buyer, gateway and token protocol paths are specific
to this repository and absent from the inherited core upstream tree at
`99143587e6babb2e577eadea0fc741cb1b413fab`; there is no upstream fix to port.

Author self-check covers callers, persistence/custody order, sibling native/token
paths, configuration and versions, rejection controls, documentation and current
base. Applicable review areas: resource bounds, concurrency, persistence, custody,
serialization, configuration, compatibility, API errors, value-moving tooling
(VM-1 through VM-9), observability, tests, build boundaries and hygiene.
A non-author review is still required before merge.

## Non-author review fixes (2026-11-26)

The non-broadcasting token preflight now precedes `BeginSend` and lifecycle send
reservation. A failed preflight leaves a call prepared, or leaves no lifecycle
send record, so a transient endpoint/build-only/JSON failure can be retried.
`TestTokenBuyerRetriesAfterAPreflightFailure` and
`TestTokenLifecycleRetriesAfterAPreflightFailure` exercise the production paths.
Only actual submission starts the durable `sending` / ambiguous outcome path.

Lifecycle attempts record the finalized wallet seqno and the native sender's
conservative `valid_until` bound. After a later finalized checkpoint is strictly
past that bound with an unchanged seqno, the old attempt is durably marked
refused (not delivered), releasing its funding reservation before a new attempt.
The regression tests cover before/at/after expiry, changed seqno, missing legacy
bounds and failed wallet reads. Unknown legacy attempts still fail closed.

Native quote validators now explicitly reject token-rail manifests. Additional
fixes propagate confirmation JSON errors, refuse decimals above 255 before
narrowing, label the threshold `minimum forward`, group imports correctly and
name `TOS_SERVICE_TOKEN_CLI_REPO` when the default fixture location is unavailable.
The configuration guide explicitly states that one agent is native-only or
token-only, never both.

All fifteen packages passed (the previous fourteen plus `quoteexchange`):
665 top-level test passes, 1,136 including subtests, with the same two existing
skips described above. Vet, spec-check, schema-check, boundary-lint, gofmt and
whitespace checks passed under the thermal guard. All twenty-one previous
controls plus seven new controls were killed, followed by the green full run.
The new controls target both preflight orders, expiry, unchanged seqno, the
strict expiry boundary, native/token manifest separation and decimal narrowing.
A separate expected-failure check with the fixture override unset confirmed
that the prerequisite error names that override. No Rust build ran.

## Explicit token expiry (2026-11-26)

Token sends no longer use the native fallback lifetime. The SDK computes the
absolute expiry once from the post-preflight send time plus the fixed two-minute
`TokenMessageLifetime`, persists it and passes that exact value to custody as
`--valid-until`. Build-only preflight also supplies an explicit expiry, so a helper
without that option refuses before a broadcast reservation. A slow preflight
cannot reuse an older budget/send timestamp.

`TestTokenSendsRecordExactlyTheExplicitExpiryPassedToCustody` drives both a real
SDK call and a lifecycle attempt through the concrete sender with a recording
custody runner. At the broadcast boundary it reads the journal and compares its
expiry with the actual command-line argument. The preflight advances the test
clock, so recomputing the bound from an earlier timestamp is detectable. Other
cases reject zero/unrepresentable expiries and refuse automatic expiry
reconciliation for attempts carrying only a default-derived bound. This run
originally retained v1 records; the coordinated pre-launch v2-only change below
supersedes that compatibility rule. The same concrete-path test
caught a raw/prefixed body-hash comparison mismatch; the sender now checks the
builder's raw hex hash separately from the CLI's prefixed output hash.

All fifteen packages passed: 668 top-level passes, 1,140 including subtests, with
the same two existing skips. Vet, spec-check, schema-check, boundary-lint, gofmt
and whitespace checks passed under the thermal guard. Thirty-four controls were
killed, followed by a green full run. The six new controls remove/change the
expiry flag, remove call/lifecycle expiry persistence, trust an inferred legacy
bound, or restore the incorrect builder body-hash comparison. No Rust build ran.

**Integration prerequisite:** the source at tos main
`4e0954507629f1b98d0bc6562882f86350076f41` and the installed helper have no
`wallet send --valid-until` option. Companion CLI support is required before live
use. The recording-runner tests prove the adapter's argument/persistence contract;
they do not claim an end-to-end run of that missing CLI option.

**Native follow-up:** native unannounced lifecycle submissions still use
`LifecycleValidUntilBound` and assume `FallbackWalletMessageLifetime`. That
fallback remains dependent on the helper's default lifetime; announced native
submissions use their reported expiry. Native behavior is unchanged here.

## Coordinated prepared-send v2 contract (2026-11-26)

Token preflight requires `tosctl.wallet-prepared-send.v2` and the numeric
`valid_until` to equal the explicit argument. The strict decoder still refuses
unknown fields. Missing, null, mismatched and v1 answers abort before the call
moves to `sending` or a lifecycle funding reservation is written. A helper that
merely accepts but ignores the flag cannot pass this preflight.

`TestTokenSendsRecordExactlyTheExplicitExpiryPassedToCustody` now exercises equal,
different, v1, missing, unknown-field and null answers for both calls and lifecycle
sends through the concrete sender. Refusals check the specific binding error and
read the on-disk journal to prove no send/reservation occurred. The positive cases
retain the slow-preflight clock and exact persisted-bound-versus-CLI checks.

There is no pre-launch journal migration: only token record v2 is accepted.
`TestLegacyTokenRecordIsRefusedWithoutChangingIt` checks reads, inventory, calls
and lifecycle sends refuse v1 with a clear error and leave its bytes unchanged.
Preserve an old journal and reconcile any pending transfer before creating a new
one; the software does not discard old records or silently reset budgets.

The native fallback remains unchanged. In addition to its inferred expiry
follow-up, native build-only preflight still expects prepared-send v1; adopting
the companion CLI's v2-only output on that rail needs its own coordinated change.
The local token preflight checks use a recording runner, not a live companion CLI.

Guarded verification passed fifteen Go packages: 668 top-level passes, 1,152
including subtests, and the same two existing skips. Vet, spec-check,
schema-check, boundary-lint, gofmt and whitespace checks passed. All 39 red
controls were killed, followed by the green full suite. The five additional
controls remove schema validation, exact-expiry validation (wrong and missing
values tested separately), unknown-field refusal, or the v1 journal refusal.
No Rust build ran.
